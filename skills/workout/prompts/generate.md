# Generate — today's workout

Load this after the check-in. Plan one session that fits today and moves toward the goals, present it in a scannable format, revise until accepted, then record it. Programming knowledge is in `references/programming.md`; load it when planning.

## Plan

Decide, in this order:

1. **What kind of day.** From the last two weeks of `log.md`: what patterns are fresh, what's been neglected, when the last hard day was. From the profile: goals, days per week, fixed days (runs, classes). From the check-in: feel, time, preference. Pick the session type and say the reason in one line.
2. **Intensity.** Normal by default; capped when tired or sore; a genuinely hard day only when the log shows recovery and the goal calls for it. A first session after a week or more away is lighter, said once.
3. **The main work.** One or two primary movements tied to a goal, with load and reps taken from `progress.md` — the last working numbers, progressed per the programming reference if the last debrief said it was solid, held or reduced if it said otherwise. If there's no number on file, program by RPE and say you'll set a baseline today.
4. **The rest.** Accessories that support the goal or balance the week, a warm-up that prepares the main movement, a short cool-down. Fit the time: warm-up about 15%, main 65%, rest of it accessories and cool-down.
5. **Substitutions.** Every limitation from the profile or check-in is honored by swapping the movement, not by "go light on it".

## Present

Scannable, in this shape. Sets × reps, load or RPE, rest. One cue or option only where it matters.

```text
<one line: type of day and why, given the week and how they feel> · <duration>

Warm-up (n min): …
Main (n min):
1. Movement — sets × reps @ load or RPE. Rest. (one-line note if progressing or holding)
2. …
Accessories (n min): …
Cool-down (n min): …

<one line inviting changes: harder/easier, shorter, swap something, different type>
```

No preamble, no motivational paragraph, no explanation of the programming beyond the first line.

## Revise

The user will ask for changes: swap a movement, shorten, harder, easier, "I hate lunges", "give me the run instead". Apply and re-show only the changed lines unless the whole shape changed. Keep every limitation intact through revisions. If a request collides with a limitation or the week's balance, say so in a clause and offer the nearest alternative — once. Then do what they say.

If a change reveals a lasting preference ("I always want to finish with a carry", "never program burpees"), do it today and note it in `progress.md` under coaching notes so it sticks.

## Record — only on acceptance

When they accept ("looks good", "let's go", "do it", "yep"): write `workouts/YYYY-MM-DD.md` with the check-in answers and the final workout, add one line to `log.md`, and update any `progress.md` coaching note learned during revision. Confirm in a line. Don't write anything before that; a draft they walk away from isn't a workout.

Then, if `next_review` is due, one line: "Also — it's been three months since we last updated your stats and capabilities. Want to do that now or after you train?" Take "later" at face value and don't repeat it this session.
